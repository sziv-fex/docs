# Standard QR Flow Tutorial

This tutorial walks through the full **Standard QR** integration:

1. Get an access token
2. Create a payment intent
3. Display the QR code
4. Optionally poll for status
5. Handle the `payment.completed` webhook

In this flow, the **merchant/POS creates the payment intent**, displays a QR code, and the **customer scans it with their wallet app** to confirm payment. FEX then notifies your backend by webhook. :contentReference[oaicite:1]{index=1}

---

## Before you begin

You should already have these credentials from your platform administrator:

- `merchant_id`
- `client_id`
- `client_secret`

Store `client_secret` securely. It cannot be retrieved again if lost. :contentReference[oaicite:2]{index=2}

You will also need:

- A backend server
- A public HTTPS webhook endpoint
- A way to display the returned QR code on your POS or checkout screen

---

## Flow overview

### Step 1: Generate an access token
All FEX API calls require a Bearer token from the OAuth2 client credentials flow. Tokens expire after **5 minutes**, so your backend should refresh them proactively. :contentReference[oaicite:3]{index=3}

### Step 2: Create a payment intent
Call `POST /merchant/api/v1/payment-intents` with the amount, order reference, and callback URL. FEX returns a `payment_intent.id` plus QR data. :contentReference[oaicite:4]{index=4}

### Step 3: Display the QR code
Use `qr_code_url` directly as an image, or generate your own QR from `qr_data`. :contentReference[oaicite:5]{index=5}

### Step 4: Wait for confirmation
The customer scans the QR and approves the payment in their wallet app. FEX sends a `payment.completed` webhook to your `callback_url`. Polling `GET /merchant/api/v1/payment-intents/{id}` every 2–3 seconds is an optional fallback. :contentReference[oaicite:6]{index=6}
